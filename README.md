# Orca 사용량 한도 워치독

Orca에서 돌아가는 Claude Code 세션이 5시간 사용량 한도에 걸려 멈추면, 한도가 풀린 뒤에
자동으로 `continue` 프롬프트를 넣어 하던 작업을 이어가게 만드는 도구입니다.

밤에 긴 작업을 걸어두고 자리를 비웠을 때, 한도에 걸린 세션이 아침까지 그대로 멈춰 있는
상황을 없애려고 만들었어요.

## 요구 사항

- macOS. launchd 사용자 에이전트와 AppKit 메뉴바 앱을 씁니다.
- [Orca](https://orca.computer) 앱과 `orca` CLI. 실행 중이어야 하고 런타임이 붙어 있어야 합니다.
- Claude Code. 한도 안내 문구를 화면에서 읽으므로 2.1 대 이상을 기준으로 맞췄습니다.
- `python3`. macOS 기본 제공 `/usr/bin/python3` 로 동작합니다. 추가 패키지가 필요 없어요.
- `swiftc`. 메뉴바 앱을 빌드할 때만 필요합니다. Xcode Command Line Tools 에 들어 있어요.

## 설치

```bash
git clone git@github.com:JinseongHwang/watchdog.git ~/watchdog
~/watchdog/bin/install.sh
```

`install.sh` 는 메뉴바 앱을 빌드하고 launchd 서비스 두 개를 등록합니다. 다른 위치에
두고 싶으면 `WATCHDOG_HOME` 환경 변수로 경로를 지정하세요.

## 왜 Orca가 필요한가

이 도구의 핵심 동작 세 가지가 전부 Orca 런타임에 기대고 있습니다.

- `orca terminal read --screen` 으로 다른 세션이 실제로 그려낸 화면을 읽습니다.
- `orca terminal send` 로 그 세션의 입력창에 키를 주입합니다.
- `orca terminal list` 로 어느 터미널이 Claude 세션인지, 아직 살아 있는지 확인합니다.

일반 셸에서는 다른 프로세스의 TUI 화면을 읽거나 거기에 키를 넣을 수 없습니다. 그래서
Orca 없이는 이 방식이 성립하지 않아요. 반대로 launchd는 그저 10분마다 한 번 실행해 주는
스케줄러일 뿐이라서, 원한다면 cron이나 다른 것으로 바꿔도 됩니다.

## 동작 방식

10분마다 살아 있는 Claude 터미널을 전부 훑으면서 화면을 읽고, 다섯 가지 중 하나로 판정합니다.

| 판정 | 화면 상태 | 조치 |
| --- | --- | --- |
| `ARMED` | Claude Code가 이미 자동 재개를 예약해 둠 | 아무것도 하지 않습니다 |
| `MENU` | 한도 옵션 메뉴가 떠 있음 | "Wait here, then continue automatically" 항목을 골라줍니다 |
| `STUCK` | 한도에 걸린 채 예약 없이 멈춰 있음 | `continue` 를 넣어 재개시킵니다 |
| `WAIT` | 한도는 감지됐지만 재설정 전 | 재설정 시각을 순찰 기록에 남기고 다음 순찰을 기다립니다 |
| `NONE` | 한도와 무관함 | 아무것도 하지 않습니다 |

Claude Code 2.1.261에는 이미 네이티브 자동 재개 기능이 있습니다. 그래서 `ARMED` 상태는
건드리지 않고 그대로 둡니다. 이 워치독이 실제로 개입하는 경우는 사용자가 자리를 비워서
옵션 메뉴에 아무도 응답하지 않았거나, 자동 재개가 취소된 채 방치된 상황이에요.

### 오작동을 막는 장치

- **배너꼴 판정**: 표지가 화면 어딘가에 있다는 것만으로는 발동하지 않습니다. 세션이 한도를
  화제로 삼아 그 문구를 그냥 출력했을 수도 있으니까요. 진짜 배너는 입력창 바로 위에 놓이는
  짧은 독립 줄이므로, 화면 아래 15줄 안에서 표지로 **시작하는** 짧은 줄만 인정합니다.
  대화 글머리(`❯`, `⏺`, `⎿`)로 시작하는 줄은 원칙적으로 제외합니다. 단, 동적 워크플로의
  `⎿ You've hit your session limit` 자식 줄은 바로 뒤의 `/upgrade` 안내와, 바로 앞의
  workflow 완료 상태 또는 사용자 후속 프롬프트가 함께 있을 때만 실제 배너로 인정합니다.
- **입력 보호**: 입력창에 사용자가 쓰다 만 초안이 있으면 건드리지 않고 넘어갑니다.
- **작업 중 보호**: 화면에 `esc to interrupt` 같은 표지가 있으면 응답 생성 중으로 보고 넘어갑니다.
- **재설정 시각 대기**: 화면에서 한도 재설정 시각을 읽어, 아직 안 풀렸으면 기다립니다.
  화면에는 날짜 없이 시각만 나오므로 어제, 오늘, 내일 중 지금과 가장 가까운 후보를 고릅니다.
- **쿨다운**: 같은 터미널에는 기본 30분 안에 다시 발동하지 않습니다.
- **launchd 경로 고정**: 전송 보조기도 `/usr/local/bin/orca`를 직접 호출해, 로그인 에이전트의
  제한된 `PATH` 때문에 재개 전송이 보류되지 않게 합니다.

## 메뉴바 앱

워치독이 지금 돌고 있는지 한눈에 보려고 macOS 메뉴바 앱을 같이 넣었습니다. 의존성 없이
AppKit 만 쓴 네이티브 앱이라 별도로 설치할 것이 없어요.

강아지가 세션을 순찰하는 컨셉으로 만들었어요. 메뉴바 아이콘의 표정이 세 가지 상태를
나타냅니다.

| 아이콘 | 상태 | 색 | 뜻 |
| --- | --- | --- | --- |
| 🐶 | 왈왈! 잘 지키고 있어요 | 초록 | launchd 에 등록되어 정상적으로 순찰하고 있습니다 |
| 🐶❗ | 문제가 있거나 순찰이 늦어요 | 주황 | 최근 두 주기 안에 실패가 있거나 점검이 지연되고 있습니다 |
| 🐶💤 | 쿨쿨 자는 중이에요 | 빨강 | launchd 에 등록되어 있지 않아 보호가 꺼진 상태입니다 |

맨 위 상태 줄은 15pt 굵은 글씨에 상태별 색을 입혀 한눈에 들어오게 했습니다. 비활성
메뉴 항목은 macOS 가 무조건 회색으로 흐리게 그려서 글씨 색과 크기를 지정해도 무시되기
때문에, 이 줄만 NSMenuItem 대신 뷰를 직접 얹어서 그립니다.

아이콘을 누르면 이렇게 펼쳐집니다.

```
🐶  왈왈! 잘 지키고 있어요
  🕐  마지막 순찰      02:01:56  ·  4분 전
  ⏭️  다음 순찰        02:11:56  ·  약 5분 뒤
  🔁  순찰 주기        10분마다
  👀  지켜보는 세션      20개
  🦴  오늘 구조한 횟수   2번
  💚  마지막 순찰 결과   무사히 다녀왔어요
  🐾  지금까지 순찰      1번
──────────────────────────────
🐾  최근 발자국
  🦴  01:16:22  구조 완료   ◐ 리팩터링 계속
  🚨  01:16:18  멈춤 발견   ◐ 리팩터링 계속
  😴  01:14:20  쉬는 중     ◐ 야간 빌드
──────────────────────────────
🔄  지금 점검 실행
🔍  점검 미리보기 (전송 없음)
📄  오늘 로그 열기
📂  watchdog 폴더 열기
⏹  워치독 중지
✕  메뉴바 앱 종료
```

상태를 보여주는 윗부분은 강아지 컨셉을 쓰지만, 실제로 무언가를 실행하는 아랫부분은
하는 일을 그대로 적었습니다. 누르면 무슨 일이 일어나는지가 비유보다 중요하니까요.

순찰 기록과 눈여겨볼 일은 로그를 한 번만 파싱한 같은 순찰 레코드를 씁니다. `점검 시작`부터
`점검 완료`까지를 한 번의 순찰로 묶어 최근 12번을 최신순으로 보여주므로, 같은 순찰의
`정상` 행과 `한도 대기` 행이 따로 중복되어 나오지 않습니다. 눈여겨볼 일은 그 순찰들 중
`WAIT`·`STUCK`·`FAIL`처럼 이벤트가 있었던 행만 고른 부분집합입니다. 따라서 아래 목록의
모든 항목은 바로 위 순찰 기록에도 반드시 있습니다. 순찰 안에서 일어난 세부 이벤트는 일지
파일에 그대로 남아 있어요.

launchd 순찰과 메뉴의 수동 점검이 겹치면 같은 세션을 두 번 읽을 수 있으므로, 먼저 시작한
하나만 실행하고 뒤에 들어온 점검은 조용히 건너뜁니다.

| 아이콘 | 뜻 |
| --- | --- |
| 🦴 | 구조 완료. 멈춘 세션을 다시 굴렸습니다 |
| 🚨 | 멈춤 발견 |
| 🎯 | 한도 메뉴에서 자동 재개 항목을 골랐습니다 |
| 😌 | 이미 자동 재개가 예약되어 있어 그냥 두었습니다 |
| ⏳ | 한도 재설정을 기다리는 중입니다 |
| 😴 | 쿨다운이라 쉬었습니다 |
| 💔 | 실패 |
| ⚠️ | 경고 |

15초마다, 그리고 메뉴를 열 때마다 상태를 새로 읽습니다.

발자국은 오늘 것과 이전 것을 나눠서 보여줍니다. 이전 기록에는 날짜를 함께 찍는데,
시각만 적으면 어제 새벽 일이 오늘 새벽 일처럼 보이기 때문이에요. 조치할 일이 없는 날은
기록이 남지 않습니다. 그것 자체가 좋은 소식이므로 빈칸으로 두지 않고 오늘 몇 번 순찰했고
모두 이상 없었다고 알려줍니다.

메뉴에서 "메뉴바 앱 종료"를 누르면 launchd 에서도 내려가므로 이번 로그인 동안에는 다시
뜨지 않아요. 다음 로그인 때는 자동으로 돌아옵니다. 비정상 종료된 경우에는 launchd 가
알아서 되살립니다.

화면 없이 앱을 점검하려면 자가 진단을 쓰세요. 메뉴바 아이템이 실제로 생성되어 보이는
상태인지, 로그 파싱 결과가 맞는지, 메뉴가 어떻게 구성되는지 전부 출력하고 종료합니다.
갓 설치해서 아직 순찰 기록이 없으면 실패가 아니라 참고 문구로 알려줍니다.

```bash
~/watchdog/bin/watchdog-menubar --selftest
```

## 디렉터리 구조

```
watchdog/
├── bin/
│   ├── orca-limit-watchdog.py        감지와 판정, 본체
│   ├── orca-send-prompt.sh           프롬프트 주입, 실행 계층
│   ├── orca-limit-watchdog-test.sh   판정 로직 단위 테스트
│   ├── orca-limit-watchdog-e2e.sh    실제 세션 종단 테스트
│   └── install.sh                    launchd 등록과 해제
├── menubar/
│   └── main.swift                    메뉴바 앱 소스
└── fixtures/                         테스트용 화면 픽스처
```

아래는 실행하면서 생기므로 저장소에 넣지 않습니다.

```
bin/watchdog-menubar                  메뉴바 앱 빌드 산출물
logs/watchdog-YYYY-MM-DD.log          일단위 롤링 로그, 30일 보관
logs/launchd.log                      launchd 자체 오류만 기록
logs/menubar.log                      메뉴바 앱 오류만 기록
state.json                            터미널별 마지막 발동 시각
```

등록되는 launchd 서비스는 두 개입니다.

- `com.jinseonghwang.orca-limit-watchdog` 10분마다 점검하는 워치독
- `com.jinseonghwang.orca-limit-watchdog-menubar` 상주하는 메뉴바 앱

## 사용법

```bash
~/watchdog/bin/install.sh --interval 300    # 점검 주기를 바꿀 때
~/watchdog/bin/install.sh --uninstall       # 서비스를 모두 내릴 때

# 지금 한 번 돌려보기. 감지만 하고 아무것도 보내지 않습니다.
/usr/bin/python3 ~/watchdog/bin/orca-limit-watchdog.py --dry-run

# 로그 확인
tail -f ~/watchdog/logs/watchdog-$(date +%F).log

# 특정 세션에 프롬프트를 직접 넣기
~/watchdog/bin/orca-send-prompt.sh --terminal term_xxxx --text "continue"
```

주요 옵션입니다.

- `--text` 재개할 때 넣을 프롬프트를 바꿉니다. 기본값은 `continue` 예요.
- `--cooldown` 같은 터미널의 재발동 최소 간격을 초 단위로 정합니다. 기본값은 1800입니다.
- `--terminal` 터미널 하나만 검사합니다. 테스트할 때 씁니다.
- `--dry-run` 판정만 하고 전송은 하지 않습니다.

## 테스트

진짜 5시간 한도는 원할 때 만들 수 없습니다. 그래서 두 층으로 나눠서 검증했어요.

```bash
~/watchdog/bin/orca-limit-watchdog-test.sh   # 판정 로직 17건
~/watchdog/bin/orca-limit-watchdog-e2e.sh    # 실제 Claude 세션 종단 6단계
```

단위 테스트는 Claude Code 바이너리에서 그대로 추출한 문구로 화면 픽스처를 만들어 판정
결과를 확인합니다. 시각에 의존하는 항목은 실행 시점을 기준으로 픽스처를 생성하므로 언제
돌려도 결과가 같아요.

오탐을 막는 픽스처가 세 개 들어 있습니다. 한도를 화제로 삼아 표지를 말로만 언급한 화면,
표지가 긴 문장 한가운데 박힌 화면, 옛 배너가 위로 밀려난 화면이에요. 실제로 이 도구가
자기 자신을 한도에 걸린 세션으로 오인한 적이 있어서, 그때 화면의 구조를 그대로 본떠
회귀 테스트로 박아 두었습니다.

종단 테스트는 진짜 Claude Code 세션을 하나 띄우고, 그 세션이 한도 배너 문구를 화면에
출력하게 만든 뒤 워치독을 돌립니다. 워치독이 지나는 경로는 실제 상황과 완전히 같고,
화면의 배너를 누가 그렸는지만 다릅니다. 테스트가 끝나면 만든 터미널을 정리합니다.

## 알려진 한계

- 감지가 화면 문자열 대조에 기대고 있습니다. Claude Code가 한도 안내 문구를 바꾸면
  `orca-limit-watchdog.py` 위쪽의 표지 목록을 갱신해야 해요. Orca가 주는 `agentWait` 같은
  구조화된 신호를 찾아봤지만 항상 비어 있어서 쓸 수 없었습니다.
- 조회가 간헐적으로 실패하면 실패로 세지 않고 다음 순찰로 미룹니다. 앱이 바쁠 때
  `terminal show` 가 빈 응답을 주는 경우가 있는데, 그것만으로 터미널이 죽었다고 단정할 수
  없기 때문이에요.
- `MENU` 판정에서 고르는 "Wait here, then continue automatically" 항목은 실제로 한도에
  걸렸을 때만 메뉴에 나타납니다. 한도가 아닌 상태에서 `/rate-limit-options` 를 열면 그
  항목이 없으므로 워치독도 아무것도 고르지 않습니다.
- Orca 앱이 떠 있고 런타임이 붙어 있어야 동작합니다. `orca status` 로 확인할 수 있어요.
- launchd 사용자 에이전트는 부팅 시점이 아니라 로그인 시점에 뜹니다. 재부팅 후 로그인
  화면에 머물러 있는 동안은 워치독도 자고 있어요.
